# Decision Log

| Field | Entry |
|---|---|
| Decision | Select Tool B as the enterprise AI coding assistant, pending a governance remediation plan |
| Date | Portfolio scenario — illustrative date |
| Owner | Program / Product Lead (decision framework owner); final approval by Executive Sponsor |
| Evidence | Weighted scoring model across developer experience, security, enterprise integration, governance, and cost (see [Scoring Model](../scoring-model/scoring-model.md)) |
| Alternatives considered | Tool A (stronger security/governance, weaker developer experience and integration); Tool C (strongest cost, weakest developer experience and integration) |
| Tradeoff accepted | Somewhat greater governance complexity, in exchange for stronger adoption potential and enterprise integration |
| Assumptions | Governance gap is remediable through vendor-side controls and internal process, not a fundamental blocker; pilot-phase developer feedback will be representative of enterprise-wide response |
| Revisit trigger | Pilot shows low adoption, unresolved security finding, or governance remediation plan proves insufficient |

## Why This Decision Is Logged, Not Just Made

Twelve months from now, someone will ask why Tool B was chosen over Tool A despite Tool A's stronger security score. This log makes the honest answer — a deliberate, named tradeoff, not an oversight — retrievable without depending on anyone's memory of the original conversation.
